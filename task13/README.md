# zen-money

Учебный проект на next.js с историей доходов и расходов. Данные хранятся в json-server.

## Запуск

```bash
npm install
npm run server
```

В другом терминале из папки `task13` запустите приложение:

```bash
npm run dev
```

Откройте `http://localhost:3000`. json-server запускается на порту `3001` и использует `db.json`.

## Структура

- `app/page.jsx` и `app/transactions/[id]/page.jsx` задают маршруты списка и подробной страницы операции.
- `src/models/transaction.js` содержит запросы к api, фильтрацию, расчёт итогов и проверку формы.
- `src/controllers` управляет загрузкой данных и действиями пользователя.
- `src/views` отвечает за отображение списка, формы, фильтров и подробностей.

В списке доступны добавление, изменение и удаление операций, фильтры по типу, категории и датам, а также сводка доходов, расходов и баланса. Нажмите на категорию операции, чтобы открыть страницу с её подробностями.

## csr, ssr и ssg

Сейчас список и подробности загружаются клиентскими компонентами после открытия маршрута. Это csr: сервер отдаёт оболочку страницы, а браузер получает данные запросами к api. Такой вариант подходит для лабораторной, потому что json-server запускается отдельно и доступен браузеру на `localhost:3001`.

При ssr сервер next.js мог бы запрашивать данные из полноценного api и включать их в html до отправки страницы браузеру. Это улучшило бы начальное отображение и доступность содержимого для поисковых роботов. Но локальный json-server не является удалённым api и не доступен серверу vercel, поэтому в этой работе данные запрашиваются в браузере.

При ssg html создаётся во время сборки. Это удобно для неизменяемых страниц, но неудобно для списка, который зависит от актуальных операций пользователя. Для такого интерфейса потребовалось бы периодическое обновление статических данных или отдельный серверный api.

## публикация

Проект можно импортировать в vercel из github: выберите репозиторий и укажите `task13` как корневую папку. Команды сборки и запуска определяются автоматически.

По умолчанию браузер обращается к `http://localhost:3001`. Это подходит для локальной работы, но на опубликованном сайте адрес будет указывать на компьютер посетителя, поэтому локальный json-server там недоступен. Для работы данных в публикации настройте `NEXT_PUBLIC_API_URL` на адрес доступного извне api. Если оставить локальную базу, опубликованная версия не будет получать реальные данные — для этой лабораторной это ожидаемо.
